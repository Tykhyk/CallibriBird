# CallibriBird

**Created by Tykhyk Zolotarov** · Copyright 2026 · [Apache License 2.0](LICENSE)

CallibriBird is a muscle-rehabilitation game. A patient plays Flappy Bird by squeezing a muscle (the forehead by default). A Callibri sEMG sensor reads the muscle over Bluetooth; sEMG means surface electromyography, the muscle's electrical activity measured through the skin. The app records the signal for the whole session and writes a report with charts.

It is meant to track, over many sessions, how well a person can **relax** a muscle and how hard they can **squeeze** it, for example during recovery from an injury.

## A session

1. **Connect:** find the sensor, check the electrodes, start recording.
2. **Who is playing?:** pick a person from the list or add a new one.
3. **Meditation:** 30 s of guided relaxation.
4. **Muscle tests:** a 30 s eyes-closed rest test, then 3 maximum squeezes of 5 s each.
5. **Calibration:** learns how strong this person's squeeze is, so the game can tell a squeeze from resting.
6. **Game:** unlimited rounds of Flappy Bird, controlled by squeezing. The therapist can change the difficulty at any time.
7. **Report:** `report.html` with the key numbers, a chart of the whole session with each step marked, and progress across earlier sessions.

Each person's sessions are saved in their own folder. A simulated sensor is built in, so the app can be tried without the hardware.

## Running it

- **Unity:** 6000.6.0f1 (Unity 6), macOS. Open the project and press Play in `ConnectScene`.
- **Sensor:** a Callibri sensor, connected directly by the app; it is not paired in Bluetooth settings. Choose **Simulated (demo)** on the first screen to try it without one.
- **Data:** saved in `~/Unity Projects/calibri/Patients' reports/<Person>/<Session>/`.

## How it works

### Built with
- **Unity 6 and C#.** The original UnityBird game is kept, and the rehab system is added in its own code module.
- **BrainBit's NeuroSDK2** to talk to the Callibri sensor over Bluetooth Low Energy.
- **Screens built entirely in code**, so each step's scene holds only a camera, a background and one screen.
- **Reports generated by the app itself** as a single HTML page with built-in charts. It needs no internet connection and no extra software.

### From muscle to bird
1. **Recording.** The sensor sends the muscle's electrical signal 1000 times a second. Its built-in filters remove slow movement and blink signals, power-line hum and high-frequency noise.
2. **Muscle strength.** The raw signal swings above and below zero hundreds of times a second, so it can't be used directly. The app turns it into an "envelope": the average strength over the last 0.1 s, in microvolts (µV).
3. **Calibration.** The person rests, then squeezes 3 times. The app learns their resting level and their strongest squeeze, and sets the flap trigger between the two.
4. **Flap detection.** The bird flaps when the envelope stays above the trigger for 0.15 s, which is long enough to ignore blinks and twitches. The next flap needs the muscle to relax below a lower release level first, so one squeeze can never count twice.

### Measuring relaxation and strength
- **Meditation and rest test:** how low and how steady the resting tension stays. The first seconds are skipped while the person settles.
- **Strength test:** 3 maximum squeezes. Strength is the steady level held, not the highest moment. Short spikes from blinking, squeezing the eyes or a moving electrode are flagged and not counted.
- **Rest as % of strongest:** both numbers come from the same recording, so differences in skin and electrode contact cancel out. That makes it the fairest single number to compare across sessions.

### Design decisions
- **Nothing freezes the game.** Bluetooth data arrives on its own background thread, and files are written on another. The game only reads finished data, once per frame.
- **Recording never stops mid-session.** The sensor streams from the Connect screen to End Session, through every round and screen change. A dropped connection pauses the game and is marked in the data and the report.
- **Accurate timing.** The sensor turned out to send about 1008 samples a second instead of 1000. The app measures the real rate, so the recording stays in step with the game events.
- **People, not file names.** Each person has their own folder and a saved ID, so their history stays together even if the name is typed differently. Simulated test sessions are never mixed with real ones.
- **Gentle on the patient.** The default game speed asks for about 30 squeezes a minute instead of the original game's 77, and the therapist can adjust it at any time.

### What each session saves
- **`report.html`:** the session document, with key numbers, a chart of the whole session with each step marked, a chart for each test, and progress across earlier sessions with links to their reports.
- **Raw recording** (`emg_raw.csv`): every sample, with its muscle-strength value and the step it was recorded in.
- **Event log** (`game_events.csv`): every flap, round, test and connection change.
- **Small result files** (`.json`) for each step. Later sessions read these for the progress comparison.

### Testing
- **73 automated tests** of the signal processing, calibration, measurements, history matching and report.
- **A built-in simulated sensor** with a realistic signal: squeezes, a detached electrode and dropped connections can all be triggered on demand.
- **Automated play-throughs** of complete sessions in Unity.
- **Real-sensor sessions**, which uncovered the blink spikes and the sensor's clock difference.

### Lessons learned
- BrainBit's signing certificate for the macOS SDK library had been revoked, so macOS refused to load it. It was re-signed locally as a stopgap until BrainBit released the same library with a valid, Apple-notarized signature, which the project now uses.
- A forehead sensor picks up the eye muscles too, so blinks look like squeezes. This is why a squeeze must last 0.15 s to count, why the trigger is always kept above the resting signal's normal wobble, and why the strength test uses the steady level.
- A small clock difference in the hardware added up to seconds of error over a session. Measuring the real rate solved it.

## Not a medical device

CallibriBird measures and records muscle activity. It does not diagnose any condition, and its numbers depend on electrode placement and skin contact. A qualified clinician should interpret the results. The software comes with no warranty (see [LICENSE](LICENSE)).
